# ChapaShop — версия v14 (новое оформление сайта, без плиток под баннером)

Магазин товаров Adopt Me с оплатой в Telegram Stars: сайт, Mini App, бот, панель владельца.
Готовы все этапы: основа и база, магазин (каталог, поиск, корзина), Telegram-бот, Mini App, оплата Stars, панель владельца, выдача заказов и PDF-чеки, безопасность и резервные копии, предстартовая проверка.

## Что внутри
| Папка/файл | Назначение |
|---|---|
| `main.py` | запуск сервера |
| `app/config.py` | настройки из переменных окружения |
| `app/models.py` | все таблицы базы |
| `app/api/` | API: каталог, здоровье, Telegram, Mini App, панель владельца |
| `app/security.py`, `app/tg_auth.py` | пароли, сессии, проверка данных Telegram |
| `app/receipt.py` | PDF-чеки |
| `app/backup.py`, `app/integrity.py` | резервные копии и проверка целостности |
| `app/preflight.py` | проверка готовности к запуску |
| `app/seed.py` | демо-товары |
| `bot/` | Telegram-бот: команды, кнопки, оплата, уведомления |
| `migrations/` | миграции базы (Alembic) |
| `web/` | сайт, Mini App и панель владельца |
| `tests/` | автотесты (этапы 1–9) |
| `Dockerfile`, `render.yaml` | запуск на Render |

## Запуск на компьютере
```
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn main:app --reload
```
Открыть http://localhost:8000 . Тесты: `pytest`.

## Запуск на Render (с iPhone)
1. Загрузите содержимое архива в новый репозиторий GitHub (приложение GitHub или github.com → «Add file → Upload files»). Файл `.env` не загружайте.
2. На render.com: **New → Blueprint** → выберите репозиторий. Render прочитает `render.yaml` и создаст сайт и базу PostgreSQL.
3. В разделе **Environment** впишите `BOT_TOKEN`, `ADMIN_PASSWORD`, `PUBLIC_URL` (адрес сайта на Render). Остальные секреты Render создаст сам.
4. Проверка: откройте `https://ваш-адрес.onrender.com/health` — должно быть `"status":"ok"`.

## Адреса
- `/` — сайт
- `/health` — состояние (секреты показываются только как настроен/нет)
- `/product/{id}`, `/cart`, `/about` — страницы сайта
- `/api/shop` — публичные настройки магазина
- `POST /api/cart/quote` — пересчёт корзины по ценам из базы
- `/api/categories`, `/api/products?q=&category=&sort=&available=`, `/api/products/{id}`
- `/docs` — документация API

## Тестовый режим
Без `BOT_TOKEN` бот и оплата работают в тестовом режиме: сообщения только пишутся в лог, счета не создаются. Стартовые товары помечены «Демо» — замените их в панели. Успешная оплата нигде не имитируется.

## Telegram-бот (Этап 3)
Команды: `/start`, `/shop`, `/profile`, `/orders`, `/roblox ник`, `/help`. Кнопки: «Открыть ChapaShop», «Мои заказы», «Профиль», «Помощь».

Подключение:
1. В @BotFather создайте бота (`/newbot`) и скопируйте токен.
2. В Render → Environment задайте `BOT_TOKEN` и `PUBLIC_URL` (https-адрес сайта). `WEBHOOK_SECRET` Render создаёт сам.
3. Перезапустите сервис. При старте сервер сам зарегистрирует webhook `/telegram/webhook`, команды и кнопку меню «Магазин».
4. В настройках магазина (таблица settings, позже — в панели) укажите `bot_username` — тогда кнопка «Оформить в Telegram» на сайте откроет бота.

Безопасность: webhook принимает запросы только с правильным секретным заголовком Telegram. Без `WEBHOOK_SECRET` он закрыт.
Тексты приветствия, помощи и уведомлений хранятся в настройках и меняются без правки кода. Если в шаблоне ошибка, бот возьмёт стандартный текст.
Без `BOT_TOKEN` бот работает в тестовом режиме: сообщения не отправляются, а только записываются в лог.

## Telegram Mini App (Этап 4)
Mini App открывается кнопкой бота по адресу `/app` (тот же интерфейс, что и сайт, но с разделами «Заказы» и «Профиль»).
- Подключён официальный скрипт `telegram-web-app.js`. Приложение шлёт `initData` в заголовке `X-Telegram-Init-Data`.
- Сервер проверяет подпись initData (HMAC-SHA256 с `BOT_TOKEN`) и срок свежести (24 ч). Telegram ID берётся только из проверенных данных.
- API: `GET /api/me`, `PUT /api/me/roblox`, `GET /api/orders`, `GET /api/orders/{id}`, `POST /api/orders`.
- Заказ создаётся со статусом «Ожидает оплаты», цены считает сервер, номер — 5 цифр без `#`, пишется история статусов, бот присылает уведомление.
- Чужие заказы не видны. Ограничение: не более 5 заказов в минуту на пользователя.
- Оплата Telegram Stars — см. раздел «Оплата (Этап 5)».
- На обычном сайте разделы «Заказы»/«Профиль» предлагают открыть магазин в Telegram.

## Оплата Telegram Stars (Этап 5)
- Кнопка «Оплатить N ⭐» в заказе Mini App (`Telegram.WebApp.openInvoice`) и в уведомлении бота (`sendInvoice`).
- Счёт создаётся через Bot API: `currency=XTR`, `provider_token=""`, payload `order:<id>`.
- `pre_checkout_query`: проверяются владелец заказа, статус «Ожидает оплаты», сумма и валюта; иначе отказ с понятной причиной.
- Заказ становится «Оплачен» только после `successful_payment`. Сохраняется `telegram_payment_charge_id` (уникален — повторное зачисление невозможно), пишется история статусов, покупателю приходит уведомление.
- Если сумма платежа не совпала с заказом — платёж сохраняется со статусом `needs_review`, заказ не отмечается оплаченным.
- Подготовлен возврат Stars (`refundStarPayment`) — кнопка появится в панели владельца.
- Без `BOT_TOKEN` — явный тестовый режим, оплата не имитируется.
- Проверено автотестами с имитацией ответов Telegram. В реальном Telegram не проверялось: нужен бот с токеном на Render.

## Панель владельца (Этап 6)
Адрес: `https://ваш-адрес.onrender.com/admin`

1. В Render → Environment задайте `ADMIN_USERNAME` (по умолчанию `owner`) и `ADMIN_PASSWORD` (длинный пароль).
2. Перезапустите сервис — владелец создастся автоматически (только если его ещё нет). После этого пароль меняется в панели: «Настройки → Смена пароля».

Разделы: **Сводка** (заказы по статусам, выручка), **Заказы** (поиск по номеру, Telegram ID, Roblox нику, фильтр статуса), **полная страница заказа** (товары, история статусов, платежи, смена статуса с уведомлением, ссылка на приватный сервер, возврат Stars), **Товары** (добавить, изменить цену, скрыть, «нет в наличии», удалить), **Покупатели** (траты и заказы), **Настройки** (тексты бота и магазина; секреты только показываются как «настроен/нет»), **Журнал действий**.

Защита: пароль хранится как хеш PBKDF2; сессия — подписанный cookie (HttpOnly, SameSite=Strict, 12 часов), смена пароля завершает старые сессии; CSRF-токен на всех изменениях; 5 неудачных входов за 10 минут — блокировка; панель нельзя встроить в чужой сайт; все тексты экранируются (защита от XSS). Статус «Оплачен» ставит только Telegram — вручную его выставить нельзя.

## Выдача заказов и чеки (Этап 7)
**Как выдать заказ (в панели, страница заказа):**
1. Заказ оплачен → блок «Начать выдачу»: вставьте ссылку на приватный сервер Roblox (только `https://`) и нажмите кнопку. Заказ станет «Ожидает выдачи», покупатель получит в боте сообщение с кнопкой «Зайти на сервер».
2. После передачи предмета смените статус на «Выдан». Покупатель получит сообщение и **PDF-чек** в чат с ботом.
3. Если выдать нельзя — статус «Отклонён» с причиной. Причина видна покупателю в боте и в истории заказа в Mini App.

**Чеки:** формируются только для заказов, оплату которых подтвердил Telegram. В панели — «Открыть PDF» и «Отправить покупателю». В Mini App на странице заказа — кнопка «Прислать чек в Telegram» (не чаще 3 раз в минуту, только свои заказы). После возврата в чеке появляется пометка «Оплата возвращена». Чек не является фискальным документом. Шрифты для чека лежат в `app/fonts` (DejaVu, свободная лицензия).

Все действия (выдача, отправка чека) записываются в журнал и в историю статусов заказа.

## Безопасность и резервные копии (Этап 8)
**Резервные копии** — панель → вкладка «Копии»:
- «Скачать резервную копию» — один JSON-файл со всеми товарами, категориями, заказами, платежами, покупателями, настройками и журналом. Пароль владельца в копию не попадает.
- У каждой копии есть контрольная сумма SHA-256: изменённый или повреждённый файл не будет принят.
- «Восстановить» — выберите файл копии на iPhone (Файлы → файл), подтвердите. Перед заменой сервер автоматически сохраняет страховочную копию текущих данных. Замена идёт одной транзакцией: при ошибке база остаётся как была. Вход владельца сохраняется.
- Копии также сохраняются на сервере в папке `backups/` (хранятся последние 10). На бесплатном Render диск временный — **скачивайте копии на телефон**.
- API: `GET /admin/api/backup`, `POST /admin/api/restore` (заголовки `X-CSRF-Token` и `X-Confirm-Restore: YES`).

**Проверка целостности** (там же, `GET /admin/api/integrity`): сумма товаров = итог заказа, у оплаченных заказов есть платёж, сумма оплаты совпадает, нет повторных платежей, платежи «на проверке».

**Защита:**
- Все маршруты панели требуют вход (автотест обходит каждый маршрут), изменения — ещё и CSRF-токен.
- Ошибки сервера отдают общий текст; в лог пишется только тип ошибки и адрес, без данных запроса и секретов.
- Ограничение размера запроса: 1 МБ (восстановление копии — до 50 МБ).
- Заголовки: Content-Security-Policy (разрешён только скрипт Telegram и показ внутри Telegram), nosniff, Referrer-Policy, Permissions-Policy, HSTS на https.
- Повторный платёж с тем же `telegram_payment_charge_id` не зачисляется дважды.
- Миграции: автотест применяет `alembic upgrade head` к чистой базе и проверяет, что схема совпадает с моделями.


## Запуск в работу (Этап 9)
Предстартовая проверка: `python -m app.preflight` или вкладка **«Готовность»** в панели `/admin` (зелёные/красные пункты, кнопка «Проверить снова»). Сервер также пишет в лог, чего не хватает.

Чек-лист перед открытием магазина:
1. Render → Environment: `BOT_TOKEN`, `ADMIN_PASSWORD` (от 10 символов), `PUBLIC_URL` (https://…). `SECRET_KEY` и `WEBHOOK_SECRET` создаются сами.
2. Перезапустить сервис и открыть `/health` — `"status":"ok"`.
3. В @BotFather: `/mybots → Bot Settings → Menu Button` указать адрес сайта (сервер делает это сам, проверьте).
4. Войти в панель `/admin`, заменить демо-товары на настоящие, указать `bot_username`.
5. Сделать тестовую покупку за 1 ⭐ и проверить выдачу и чек.
6. Скачать первую резервную копию на телефон.
